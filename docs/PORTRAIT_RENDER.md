# 保存 EDL 的固定中心 9:16 输出

竖屏由保存的横屏 EDL 派生为一个新版本。原片段顺序、源帧范围、溯源、帧率、原分析和历史人评都不改变，不重新识别或评分。当前范围是固定中心裁剪，不包含人脸跟踪或自动主体取景。

## 版本与几何

EDL 0.1.0 的原契约和 Schema 保留，源尺寸必须等于工程尺寸。新增 `edl-v0.2.schema.json` 描述 EDL 0.2.0：`profile` 是输出尺寸，`sources` 仍是实测原尺寸；`framing.sources` 按源顺序完整记录每个源的 `source_id/x/y/width/height`，不能把原横屏素材描述伪装成竖屏。

输出为偶数尺寸、精确 9:16，帧率保持一致。以源宽高 `W/H` 计算 `k = floor(min(floor(W/9), floor(H/16))/2)*2`，裁剪尺寸为 `9k × 16k`。居中位置再向下对齐到偶数像素，中心偏差最多 1 像素，以保持 YUV420 色度对齐。尺寸、位置、源覆盖和顺序都重新计算核对，不能改成任意窗口却继续标为中心裁剪。

1920×1080 的实际例子：裁剪矩形为 594×1056，左上角 `(662,12)`，再按同一比例缩放至 1080×1920。保持精确比例的整数裁剪会同时舍去少量上下边缘；没有横向拉伸或旋转画面。`create_portrait_edl()` 可为离线验证指定其他偶数 9:16 输出尺寸，任务 API 固定为 1080×1920。

FFmpeg 直接读取原归一化素材：整数帧 trim → 源坐标 crop → 输出 scale → 拼接 → 字幕。原音轨、采样范围、时间基准和切点算法不变，不把上一轮横屏成片再次编码作为输入。

## 保存与接口

`POST /tasks/{task}/edl/{revision}/portrait` 创建新 EDL 版本，返回新版本的 Location。服务保留原 `media-profile.json`、`candidates.json` 和 `analysis.json` 的原始字节与 SHA；新版本元数据绑定原 EDL 文件 SHA 和父版本编号。读取时仅允许横屏原版本作为父版本，再完整重建派生 EDL 比对，防止循环版本、改切点或替换分析。原素材持锁核对，不另复制媒体。

在新版本上调用现有字幕和渲染接口即可。新字幕按竖屏每行 12 个 CJK 字符、最多两行分组，字体受实际画布与文本宽度约束；极长词保留原文并使用可信数字字号缩小，无法容纳时明确失败。横屏版本原 18 字策略、计划和 ASS/SRT 字节兼容保留。字幕不能复用旧横屏版本的时轴/布局文件；保存的词时间不会重写。

成片报告包含实际输出尺寸和保存的 `framing`，渲染服务创建与读取均核对裁剪记录等于 EDL；下载继续核对并持有同一文件句柄。独立图像验证另核对真正裁剪的区域，报告字段本身不等于画面证据。

```powershell
$env:PYTHONPATH = 'backend'
python -m clipforge.services.editing <task-id> --portrait-from <original-revision-id>
python -m clipforge.services.subtitling <task-id> <new-revision-id> --font-name '<configured-font-family>'
python -m clipforge.services.rendering <task-id> <new-revision-id> --subtitle-id <new-subtitle-id> --font-file <font-file> --font-name '<configured-font-family>' --timeout 3600
```

沿用第二周的工具配置以及 [字幕配置](SUBTITLES.md)。API 镜像资源校验已补新 Schema，未实际构建或部署容器。后续 React 已接入这些 API，并完成一次真实 [网页导出流程核验](WEB_EXPORT.md)；本地预览与现有生产服务仍分开。

## 核验与剩余范围

### Test3 的实际取景结论

2026-10-12 对六组同源帧进行横屏／竖屏对照。1920×1080 原图的保存裁切为 594×1056@(662,12)，只保留原宽度的 30.94%。原帧 400 的双人对谈中，左侧嘉宾从竖屏画面中消失；原帧 1200 的左侧白衣说话人也被舍去。样例尺寸、坐标、帧序可复现，但这份录屏的固定中心取景不适合直接交付，建议使用横屏导出。

同帧截图及判断见 `docs/evaluation/week5-export/framing-comparison.jpg` 和 `framing-suitability.json`。六帧能证明这些具体失败，不是整片人物保留率或通用适用性评测。如果必须竖屏，可后续加入完整画面留白或逐场景预览并调整取景；本轮未实现这两种策略，不能把放大输出到 1080×1920 当作恢复了丢失的画面。

工作区 `outputs/week5-portrait/` 保存本轮实际脚本、源码 SHA、几何/帧序/音频/字幕检查和真实 Test3 成片记录，以最终 JSON 结果为准。真实样片沿用技术对照片段，不新增人评或叙事接受标签；素材本身是浏览器录屏，中心裁剪仍可能舍去边缘内容。

2026-10-12 实际结果：相关回归 184 项，183 通过、1 项 Windows 下跳过；核心渲染执行行试测 500/556、89.93%，仅 mock 工具的核心行范围，不是完整 CI 或分支覆盖。两个实际竖屏小样本共 136 帧，源编号、PTS、裁剪坐标、原音轨顺序、字幕出现/消失和 AI 标识均通过；8 项变更数组负控制拒绝。最大合成音频同步误差 0.00250 帧。理数帧率下字幕首次显示相对原始分数词时间可迟 1.5 帧，不能把导出时标精度当作真实语音准确度。

真实 Test3 已一次编码生成 1080×1920、30 fps、2180 帧、21 条字幕。首尾及切点两侧四帧严格对应源帧 43/1681/112/652，全片未覆盖区域也与固定裁剪参照一致。原任务 16 个文件、指定旧版本 17 个文件和任务记录全部未变。实际截图确认新增文字可读，同时固定中心裁剪舍去了部分人物，录屏中的浏览器栏、旧字幕和弹幕仍保留。首次核验脚本误把全片 AI 标识的向上取整结束时标按词字幕要求检查，已修正并归档；复用同一编码，没有修改产品或重渲染。

本轮不会宣称原 ASR 与真实人声达到 ≤0.3 秒。此验收、完整 HTTP/容器检查及 Shotcut GUI 样例仍保留。后续已实现 [MLT 裁切、字幕与不可变导出](MLT_EFFECTS.md)：同一 EDL 0.2 的 native 像素 crop 被写入 source chain，字幕使用最终时间线整数帧；不再因竖屏版本而拒绝。新效果五例共 87 帧、13 条 cue 的原生核验通过，含音单帧片段的引擎限制则明确拒绝并提示导出 MP4。GUI 编辑保存可能将 native 裁切单位转换或舍入，需单独核对读回；原生结果与上述 MP4 结果都不替代 GUI 验收。
