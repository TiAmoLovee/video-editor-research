# 自动首尾优化接入记录

2026-10-09：将新素材 New4 实验中使用的句子边界选择接入视频任务处理、结果缓存、下载接口及候选页面。此更新在本地准备，尚未部署或推送。

## 用户可见行为

开启后，新任务保留原候选及分数，并在“边界优化试听”中提供优化范围的视频和下载。调整后的范围不继承原评分，也不会自动标为人工通过。未确定或重复的范围仍占一个候选位置，不隐藏失败项。

默认关闭。开启时使用规则基线，向配置的模型服务发送转写及候选时间。源视频留在本机处理。完整批次返回并通过校验后才生成可下载结果；模型异常、额度不足或格式无效时停止调用，保留原候选，失败不重试。媒体生成失败则任务失败，不发布部分视频。

- 后端全部 387 项测试通过；Ruff 通过。
- 前端全部 36 项测试通过；TypeScript 检查及生产构建通过。

- 对一个已审查范围实际运行新媒体生成入口，校验帧数、音视频时长和源文件哈希。
- 失效输出不缓存；缓存命中不再调用模型；配置变化使缓存失效。未知用量保留预算预留，并阻止后续模型请求。

重放证明流程接入与已审查输出一致，不代表一次新的模型质量实验。此次尚未执行目标电脑上的 Docker 更新或完整在线上传回归。

## 85% 判据与保留的问题

[New4 原始人工结果](evaluation/new4-20261009/result.json)：19 个原始位置全部评完，首尾完整为 17/19（89.47%），四项同时通过亦为 17/19。S02 和 S14 的结尾不完整，记录保留。此结果达到这一个新素材批次的 85% 目标；样本来自同一视频且范围重叠，不能宣称所有素材普遍达到 85%。

## 部署配置

Docker 按顺序组合 `compose.yaml`、`compose.asr-small.yaml`、`compose.boundary.yaml`，私下导出模型密钥并设置 `CLIPFORGE_BOUNDARY_CONFIG_FILE`。本机开发设置 `CLIPFORGE_BOUNDARY_REPAIR=1` 和 `CLIPFORGE_BOUNDARY_CONFIG`。

示例配置的 `initial_used_tokens=0` 仅用于新的额度账本。本次继续已有实验必须使用交付包里的私有配置：`initial_used_tokens=91987`、`max_total_tokens=200000`，剩余 108013。账本存于现有数据目录 `boundary-budget.sqlite3`，只在首次创建时加载初始用量。不要删除数据卷或账本来恢复额度。模型服务的“免费额度用完即停”设置仍由用户在平台保留。

此更新不包含模型文件、视频、密钥或新的媒体备份。
