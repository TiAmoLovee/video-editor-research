# Test3：base 与 small 模型对比

日期：2026-09-28。用户提供人工转写，并确认五个片段的文字和时间均已核对。本次使用原始 Test3.mp4，源文件 SHA256 与已验收任务一致；只在工作副本实验，原项目与运行中的服务未修改。

## 结果与选择

| 模型与过滤 | 字符错误率 | 替换/遗漏/多出 | 本次转写耗时 | 已确认音乐区间的误转写词条 |
|---|---:|---:|---:|---:|
| base + Silero | 23.38% | 44/8/2 | 11.36 秒 | 0 |
| small + Silero | 19.48% | 21/13/11 | 50.54 秒 | 0 |
| base，无过滤（诊断） | 34.63% | 31/8/41 | 22.65 秒 | 14 |
| small，无过滤（诊断） | 16.88% | 15/13/11 | 38.79 秒 | 1 |

small 开启过滤时比同环境 base 少 9 次字符编辑，CER 降低 3.90 个百分点；本次转写约慢 4.45 倍。它改善了“蚂蚁”“自贡”以及部分“刘慈欣”，但另两处人名仍为“刘慈禧”，还有漏字、数字写法和语句错误。因此保留 base 为默认，提供 small 作为显式可选方案，不宣称整体识别质量已达标。

两个模型关闭过滤时均重新产生音乐误转写。虽然 small 无过滤的全文 CER 较低，它仍不满足本次音乐场景要求，不能只按总分选择。交付代码始终保留 Silero。四种条件均没有输出“一夜之间”，不能把这次开头遗漏简单归因于语音过滤；原因尚未通过逐段试听定位。

## 比较口径

- 从 `C:/Users/asus/Desktop/Sucai/Test3.mp4` 读取原片，仅在工作副本归一化一次；两个模型读取完全相同的 16 kHz PCM。原文件与 PCM 哈希保存在实验记录。
- 本地归一化输出仍为 72.6 秒，但字节哈希与 Docker 成品不同，因此不能把本次 small 直接与历史服务的 base 19.48% 相比。相同的 19.48% 数字是巧合。
- CPU int8、4 线程、beam=5、temperature=0、自动语言检测，其他解码参数与现有服务相同。没有加入参考原文、人名提示、热词，也没有按错误结果调阈值。
- 将全文做 NFKC、大小写统一、忽略空白和 Unicode 标点，以 231 个参考字符为分母计算字符编辑距离。保持既有口径，不把“3体20周年”和“三体二十周年”等写法自动等价；分句位置不影响计分。
- 每个条件只测一次，时间包含 VAD/识别/词时间处理和简体转换，不含模型加载、FFmpeg、排队和打包，不是稳定性能基准或缓存成绩。
- 用户确认的是片段级时间；本轮不验收逐词 ≤0.3 秒，也不评估自然句界。Test3 已用于开发，不属于独立留出集。

## 代码与模型

- 新增固定版本 small 注册与 SHA256 校验、`CLIPFORGE_ASR_MODEL=base|small`，模型目录可继续显式指定。
- CLI 支持 `python -m clipforge.analysis.model --model small --check`。模型文件缺失或与所选型号不匹配时明确失败，不自动下载，不悄悄退回 base。
- ASR 输出记录实际选择的模型仓库、revision 和文件哈希，缓存键包含型号。
- 新增 `compose.asr-small.yaml`；只使用原 `compose.yaml` 时仍为 base。使用 small 的后续构建/启动均须带两个 `-f` 参数。
- 不改本轮分句规则。分句仍有断词问题，应单独优化和验收，不能把模型切换视为已解决。

125 项后端测试、Ruff、small Compose 配置检查通过。small 的真实流水线验证覆盖无音轨、静音、公开中文样例，检查完整契约与 ZIP/独立 JSON 一致；另验证 Test3 音乐切片为空及低音量中文样例有转写。队列为测试替身，尚未部署到用户 Docker。未重测未改动的前端。

模型来源：[Systran/faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small/tree/536b0662742c02347bc0e980a01041f333bce120)。small 为固定版本本地模型，下载文件已按官方 LFS SHA256 / Git blob 身份验证；交付附 MIT 许可。参考：[faster-whisper VAD](https://github.com/SYSTRAN/faster-whisper#vad-filter)。
