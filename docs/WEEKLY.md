# ClipForge 每周工作记录

## 第二周：媒体流水线骨架与最小闭环

### 本周目标

完成“上传视频 → 后台处理 → 进度显示 → 下载切片”的最小流程。视频归一化为 CFR 30 fps / H.264 / AAC，按每段最多 30 秒切片。

当前已完成本地媒体处理模块初版，尚未接入后端任务接口和前端页面，MVP-0 整体闭环仍在开发中。

### 本周完成

#### 1. 开发环境与 Git 工作流程

- 使用 Git 命令克隆仓库，核对分支、远程地址和提交历史。
- 创建第二周开发分支 `week2/mvp0`，练习本地修改、检查差异、暂存、提交和远程同步。
- 安装并验证 Python 3.11.9，创建项目独立环境 `.venv`。
- 配置 `.gitignore`，忽略虚拟环境和 Python 缓存文件。

#### 2. 视频信息读取与统一格式

- 实现 `probe.py`：调用 FFprobe，将 JSON 输出解析并整理为项目统一的视频信息结构。
- 新增 `schemas/media_meta.schema.json`，定义字段类型和未知值的表示方式。
- 使用 `Sucai1.mp4` 验证读取结果：时长约 41.27 秒，分辨率 960×600，视频编码 HEVC，平均帧率 30 fps，音频编码 AAC、44.1 kHz、单声道。
- 保存元数据样本 `docs/samples/media_meta.json`。

#### 3. 视频归一化转码

- 实现 `normalize.py`，复用视频信息读取功能，将素材转为 H.264 / AAC、恒定 30 fps 的 MP4。
- 实现原素材保护、已有输出拒绝覆盖、转码超时及失败处理。
- 真实素材转码后，基本参数检查和人工播放检查通过。
- 助手另行检查 Python 转码产物的 1,238 帧时间戳，相邻帧间隔均为 1/30 秒。
- 补充 `docs/NORMALIZATION.md`，记录运行方法、验证结果和当前限制。

#### 4. 固定时长自动切片

- 实现 `split.py`，按每段 900 帧规划切片，在 30 fps 下对应每段最多 30 秒。
- 根据切片清单执行转码，保存 `clip_plan.json`，记录片段边界和帧数。
- 真实归一化素材自动生成两段，经程序检查分别为 900 帧和 338 帧。
- 补充 `docs/SPLITTING.md`，记录运行方法与验证范围。

#### 5. 自动化验证

- 全部 22 项单元测试通过：7 项元数据转换测试、7 项转码约束与文件保护测试、8 项切片边界与目录保护测试。
- 运行 `tests/integration_split.py`，真实调用 FFmpeg，以下媒体集成实验通过：
  - 5 分钟、9,000 帧的合成素材生成 10 个切片，每段 900 帧。
  - 901 帧的合成素材生成 900 帧与 1 帧的两段，保留真实尾帧。
  - 编码器缺失时正确返回失败，不遗留最终结果目录或临时目录。

以上是本地媒体模块验证，尚不等同于通过后台接口提交视频并获取结果的系统集成测试。

### 未完成及原因

- **后端任务流程**：FastAPI、Celery、Redis 和任务数据库尚未搭建；当前优先完成本地媒体处理模块。
- **前端操作流程**：上传、进度展示和结果下载页面尚未实现，需要先明确后端接口。
- **接口文档与系统集成测试**：OpenAPI 文档及“提交 5 分钟视频后返回 10 个切片”的接口测试尚未完成，依赖后端任务流程。
- **长视频与恢复能力**：尚未验证 60 分钟 1080p 视频处理、刷新页面恢复进度，以及服务重启后任务状态保留。
- **验证完善**：尚未接入自动 JSON Schema 校验；逐帧 CFR 检查尚未纳入常规自动化测试；切点处音频衔接与音画同步误差尚未进行自动测量。
- **持续集成**：测试目前在本地运行，仓库原有占位 CI 尚未升级为真实代码检查和测试。

### 技术障碍与当前假设

- Python、FFprobe 和 FFmpeg 已能在本机运行，当前媒体模块验证已通过；Redis 和后台工作进程的运行环境尚未核对。
- 当前使用 Windows。下一步需要确认 Celery 与 Redis 的部署方式，并通过一个最小后台任务验证“提交 → 执行 → 查询结果”的流程。
- 当前使用 Shotcut 自带的 FFmpeg 8.1 系列，与任务书列出的 6.1 / 7.x 不同。已记录本机版本，尚未验证其他版本的兼容性。

### 失败的尝试

- **Git 直连推送失败**：出现连接重置或无法连接 GitHub 的错误。显式使用本地代理，并完成 Git 身份认证后，推送成功。
- **安装后终端找不到 Python**：`python` 命令仍指向 Windows 商店入口。确认实际安装成功后，改用 `py -3.11` 和项目虚拟环境中的解释器，运行成功。
- **工作记录未进入暂存区**：文件保存时间晚于此前的 `git add`，导致提交预览中缺少该文件。保存后重新暂存，修改正常进入待提交内容。
