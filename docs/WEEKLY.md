## 第二周：媒体流水线骨架与最小闭环

### 本周目标

完成“上传视频 → 后台处理 → 进度显示 → 下载切片”的最小流程。视频归一化为 CFR 30 fps / H.264 / AAC，按每段最多 30 秒切片。

当前已完成媒体模块、FastAPI 与 Celery/Redis 视频任务接入，以及浏览器上传、历史任务、阶段进度和下载页面。2026-09-22 在实际 Docker 部署中走通页面最小闭环；已补充重启操作后的已完成任务与下载文件对比，结果一致；60 分钟合成素材处理与首次真实 CI 已通过；基本异常输入验收也已完成；完整性能数据和资源故障等场景仍待补齐。

### 失败的尝试

- **Git 直连推送失败**：出现连接重置或无法连接 GitHub 的错误。显式使用本地代理，并完成 Git 身份认证后，推送成功。
- **安装后终端找不到 Python**：`python` 命令仍指向 Windows 商店入口。确认实际安装成功后，改用 `py -3.11` 和项目虚拟环境中的解释器，运行成功。
- **工作记录未进入暂存区**：文件保存时间晚于此前的 `git add`，导致提交预览中缺少该文件。保存后重新暂存，修改正常进入待提交内容。

- **Docker 镜像拉取超时**：Docker Hub 认证和下载曾超时，明确配置 Docker Desktop 的本地 HTTP 代理后成功拉取基础镜像并构建服务。
- **API 端口冲突**：宿主机 8000 已被 Docker 服务占用；将 ClipForge 映射改为 `127.0.0.1:8200:8000`，启动及 HTTP 集成测试通过。
- **Compose 配置缺少服务**：一次检查发现配置仅保留 Redis，补齐 worker 与 api 后恢复启动。

- **Trixie 镜像构建认证超时**：构建过程获取 Docker Hub 令牌失败，在当前 PowerShell 设置 HTTP_PROXY、HTTPS_PROXY 和本地地址 NO_PROXY 后继续构建成功。
- **切片数量测试预期错误**：更换为 345.5 秒素材后仍指定 `--expected-clips 2`，实际正确生成 12 段，导致测试断言失败。更换素材时应按时长设置预期，或不指定固定段数。
