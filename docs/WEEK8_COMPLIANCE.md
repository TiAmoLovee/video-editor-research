## 本次实现

`backend/clipforge/compliance.py` 定义统一的项目内部标识约定；新 EDL MP4 在编码时写入以下字段，随后由 FFprobe 读回。缺失、类型或值不一致时拒绝发布新成品。

| 字段 | 固定值 | 含义 |
| --- | --- | --- |
| `clipforge_editing` | `AI-assisted-editing` | AI 辅助编辑，不声称素材由 AI 生成 |
| `clipforge_tool` | `ClipForge` | 处理工具标识 |
| `clipforge_marking_version` | `1` | 本项目标识约定版本 |

保留原有 `comment=ClipForge EDL renderer 0.1.0` 和 `editing=ClipForge`；`+use_metadata_tags` 使新增键保存在 MP4 中。验证报告新增 `output.identification_metadata` 和 `checks.output_identification_metadata_match`。这些是项目自定义字段，不能写成已经实现 GB、C2PA 或其他外部标准。

普通成片、带字幕成片及逐片 ZIP 批导都经过 `render_edl`，因此新导出统一获得这三项字段。标识策略没有改变 EDL 的源帧范围、时间轴或 Schema。

历史保存输出仍按原完成记录和哈希读取；没有给旧视频补写字段，没有修改第七周冻结评测视频或人工答案。旧成品通过历史读取校验，不等于通过本次新增标识检查。

## 只读检查命令

在仓库根目录运行：

```powershell
python tools/week8/check_export.py path/to/output.mp4 --ffprobe path/to/ffprobe.exe
```

可追加 `--output new-report.json` 保存新报告；已有文件不会覆盖。默认探测超时 30 秒，可用 `--timeout` 设为大于 0 且不超过 300 秒。

- 退出码 `0`：MP4 视频的这三项元数据符合约定。
- 退出码 `1`：容器／视频流或标识字段不符合约定。
- 退出码 `2`：输入、探测、超时或报告写入出错。

检查器先后计算输入 SHA-256，拒绝检查期间发生改变的文件。FFprobe 诊断不直接回显到用户；JSON 解析量限制为 1 MiB。报告固定声明 `scope=metadata-only`、`visible_label.status=not_checked` 和 `legal_compliance_assessed=false`。**纯色视频也可以带正确元数据，所以退出码 0 绝不证明画面包含可感知的标识。**
