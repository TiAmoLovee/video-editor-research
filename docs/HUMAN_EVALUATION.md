## 四项判断

每项必须显式回答 `yes` / `no` / `uncertain`，没有默认答案：

1. `opening_complete`：开头是否完整，没有从半句话开始。
2. `ending_complete`：结尾是否完整，没有截断半句话。
3. `understandable`：不看原片能否理解内容。
4. `no_unrelated_content`：是否只包含相关内容，没有混入无关场景。

首尾完整率＝前两项均为 yes 的条数 / 固定 10 条；四项均为 yes 的比例另计“可用率”。uncertain 不算通过且不移除分母。未评完时所有比例及达标标志为 null，仅展示已评数量和已确认通过数。10 条需至少 9 条通过才能达到本批次 85% 目标。

该单素材、多重叠范围试评不是独立代表性样本集。New1 还包含 Test3 相同题材与对话，因此即使本批次达到 85%，`overall_week4_acceptance` 仍为 `not_established`。后续需固定更广素材和评审方案，再验证整体交付标准。

## 本地工具

`python -m clipforge.decision.evaluation --analysis <analysis.json> --candidates <candidates.json> --source <normalized.mp4> --output <新目录> --source-name <展示文件名> [--ffmpeg <路径>] [--ffprobe <路径>]`

渲染目录必须全新；失败批次只保留 plan 和诊断文件，不能作为就绪批次使用。它不覆写原候选、模型缓存或成品。

`python -m clipforge.decision.evaluation_server <批次目录> --port 8307`

评测服务只监听 127.0.0.1，是独立本地辅助工具，不改正式 8200 Docker 或 8306 只读任务工作台。用户从页面提交每条四项判断及可选备注；服务绑定清单、校验来源与修订号，保存独立不可覆盖的 `reviews/review-000001.json` 等版本。多页面旧修订写入返回 409，避免覆盖新反馈。评审导出包含冻结清单、当前反馈和口径。浏览器刷新可以恢复已保存记录；当前尚未保存的选择会在离开前提示。

入口加载即校验媒体哈希；播放时再次校验。保存仅接受本地同源 JSON 请求，不向云端发送原文或评分。真实批次不能写入用于测试的假反馈，测试仅使用临时目录的合成样例。
