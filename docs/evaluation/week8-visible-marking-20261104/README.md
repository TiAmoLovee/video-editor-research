上述是特定媒体实验的场景和帧数，**不是全仓库测试总数或最终全部通过结论**。重复运行的同类证据没有累加。EDL、ZIP 和 MLT 的检测方法不同，指标不能直接当作统一准确率。

EDL 的输出依次取源帧 `[0,90)`、`[150,240)`；全部 180 帧使用水印区域外的二进制条码核对。每例保存输出帧 0、89、90、179，覆盖首末帧和切点两侧，中间帧 90 与切点重合。未加标识的源视频对照全部 300 帧的目标区域变化为 0。三个 ZIP 片段分别核对 `[1,9)`、`[37,48)`、`[103,112)`，最大条码灰度误差为 1，源切点误差均为 0 帧。旧分析样本、源媒体和历史 ZIP 未被修改。

MLT 使用相同 qtext 滤镜、透明文字作为像素对照。源区间在工程结构中核对，没有执行 EDL/ZIP 使用的独立源帧条码检测。其消费者仅输出视频，未验证音频输出、GUI 保存重开或第三方终端导出。

## 已知反例与证据边界

本快照时，FFmpeg/ASS 共享布局仍允许 **160×2** 画布；真实解码的 1 帧为全黑、可见标识像素为 **0**，但渲染记录报告 `all_output_frames=true`。`known_counterexample_at_snapshot` 保留该反例及原报告哈希，**状态为待修，不计入正向通过样本**。后续修复应另加验证证据，不回写原反例。

后续修复已完成：共享布局和新字幕导出增加完整文字框预检，14×180、160×2、160×16 均在编码前拒绝；160×48 的 Noto 单帧样本仍成功并实际显示标签。[修复证据](tiny-layout-fixed.json)保留原报告哈希，原反例不改写。97 项相关回归全部通过；随后仅将三个 Python 文件规范为 LF，再跑 21 项核心，全部通过、无跳过。另见 [首次全量结果与修复](local-regression.json)，其中沙箱硬链接错误需要独立 CI 确认。

160×48 的 ZIP 样本证实存在标识像素，不证明原尺寸文字易读。ROI 检测不是 OCR，也不能保证所有复杂背景的可读性；字体报告和 metadata 不替代像素检查。代表截图已另存用户交付目录，并保留原 PNG 字节。本目录不宣称法律认证、任意尺寸覆盖、Docker 重建完成或全量测试完成。

最初 12 个 EDL 场景未记录实现代码的前后哈希；后 6 个 fit_pad 场景记录了四个渲染相关文件的哈希，运行前后一致。原报告中的 UTC 时间为 11 月 3 日晚，对应本地 11 月 4 日；MLT 原报告未提供运行时间，摘要没有补造时间。
