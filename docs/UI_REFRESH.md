# ClipForge 工作台 UI/UX 改版

> 本文是 2026-09-22 阶段记录；其中单文件前端和根目录模块描述对应历史版本。2026-09-24 工程整改的当前目录、技术栈和待验收项见 [ENGINEERING_REFACTOR.md](ENGINEERING_REFACTOR.md)。

本次以第二周已合并的 `7521cba` 为基础，保留上传、后台处理、历史任务和下载接口，对操作页面进行视觉与交互整理。开发分支为 `feat/ui-workbench`。

## 页面变化

- 深色导航、浅色工作区和紫色主操作，统一字号、间距、圆角、状态标记和焦点样式。图标为页面内 SVG，不依赖外部字体、图床或前端构建工具。
- 支持点击或拖拽选择一个视频；展示文件名、大小和移除按钮；空文件、超限文件和不支持的扩展名在上传前提示。未选择有效文件时禁用提交，上传期间锁定选择与移除。
- 展示读取、转码、切片、打包、完成五个步骤，区分失败、排队、运行和完成状态。百分比仍为后端阶段估计，不是逐帧进度。
- 切片可按文件名或序号搜索；初次最多展示 24 段，按需每次追加 24 段。搜索覆盖任务的全部切片，不局限于当前已展示部分。
- 点击切片预览后才设置播放器地址，不自动播放；关闭预览或切换任务时释放视频资源。浏览器无法播放时提示下载后观看。
- 手机窄屏按上传、处理结果、历史任务排列，避免用户先滚过历史列表才能看到结果；选择任务后滚动到详情。页面内导航保留地址栏任务编号。
- 服务连接中断时展示重试提示；连接标记只表示页面能读取 API，不保证 worker 就绪。

## 验证记录（2026-09-22）

本轮在独立本地预览服务中验证，任务记录与媒体文件使用工作区副本。预览使用相同 FastAPI 路由与真实媒体处理函数，本地工作线程代替 Celery 调度；FFmpeg 使用开发机 Shotcut 版本。本轮不重复宣称 Docker/Celery 部署验收。

- 原有 43 项 Python 单元测试全部通过；页面 JavaScript 语法检查通过。
- 1440 像素桌面和 390 像素窄屏检查：布局正常，无页面横向溢出。手机结果区在历史列表之前。
- 浏览器选择真实 `Sucai1.mp4`，显示文件大小，提交后生成任务 `70939627-f680-4d6e-91ab-06b24e325897`，最终完成 2 段；点击 ZIP 链接捕获下载事件。
- 已有真实切片 `clip_002.mp4` 预览读取到 960×600、时长约 11.27 秒，按播放键后 `paused=false`，未返回媒体错误；关闭后移除播放器地址。
- 载入此前已核验的 60 分钟素材结果副本，首次显示 24/120，追加后 48/120；搜索 `120` 找到末段，搜索不存在的名称展示空结果；刷新后恢复所选任务。
- 使用现有异常集成脚本验证：无效扩展名 415、空文件 422、损坏媒体 FAILED、失败任务 ZIP/MP4 下载 409、失败后正常视频可成功并校验 ZIP。浏览器中失败任务没有下载入口。
- 上述浏览器交互中未捕获控制台错误。拖拽分支已实现，但本轮浏览器工具未提供桌面文件拖入操作，不能将其记为实际拖拽验收。

## 应用到现有 Docker 服务

将本分支代码同步到本地后，在项目目录执行：

```powershell
docker compose up -d --no-deps --build api
```

然后刷新 `http://127.0.0.1:8200/`；如仍显示旧样式，使用 Ctrl+F5。这一步只重新构建 API，不重建 worker，也不删除数据卷。正在上传文件时先等上传结束再更新 API。

## 范围与限制

不改变媒体处理规则、数据库或任务生命周期，不新增自动重试、取消任务、精确处理百分比或多用户隔离。切片预览依赖浏览器对生成 MP4 的支持；下载入口继续沿用服务端成功状态和文件清单校验。
