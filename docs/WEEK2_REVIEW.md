# 第二周成果与验收说明

记录日期：2026-09-22。请在 GitHub 切换到 `week2/mvp0` 分支查看，回到[仓库首页](../README.md)，或先阅读[交付摘要与运行版本](WEEK2_DELIVERY.md)。

## 本周交付是什么

本周将第一周的调研推进为可运行的媒体处理原型：通过网页上传视频，由后台转为 H.264 / AAC、CFR 30 fps，按每段最多 900 帧切片，再通过网页下载。最后不足 30 秒的尾片保留。

这一步解决基础媒体流程；镜头检测、语音活动检测、转写、语义推荐和人工编辑仍是后续工作。当前 `clip_plan.json` 记录固定切片的帧边界，不等同于已经交付完整 EDL 编辑系统。

1. 阅读 [README](../README.md) 的启动步骤，或在已运行的开发机打开 http://127.0.0.1:8200/ 。该地址只能访问查看者自己的本地服务。
2. 选择历史任务 Test1.mp4，展示 12 段结果、单段下载和 ZIP 下载。
3. 选择 Sucai1.mp4，展示 30 秒与约 11.27 秒的两段，说明尾片不会丢弃。
4. 刷新当前页面，确认仍选中相同任务；打开 ZIP，查看切片及三个 JSON 记录。人工播放时检查画面、声音和尾段。
5. 查看下表中的验收证据，再查看 Git 提交历史和周报。

历史任务只存在于当前开发机的数据卷，不随 Git 克隆到其他电脑。新电脑演示需先用自己的素材提交任务。本次长视频任务已完成，可以从历史任务中查看 120 段结果。后续有任务执行时，避免重启服务中断处理。
