# 第四周整改：记录采纳后的人工修改量

2026-10-13。此功能已在本地源码接入第五周的统一 EDL 和网页编辑流程，尚未发布或部署到 8200。本轮不调用模型、不重新转写、不复制视频。

## 使用与基线

先将候选保存为一个采纳版本，再点击“编辑这个版本”。按源视频的整数帧调整切点，可以重排、删除或加入当前所选的新片段，最后“保存修改为新版本”。新增片段的帧位置只从该版本保存的候选快照读取，不使用当前排名或浏览器的秒数取整。至少保留 1 条，最多 100 条。源止帧不包含在片段内，与原 EDL 契约一致。

首次采纳版本固定为基线；后续编辑始终保留它的编号和文件哈希，同时绑定直接父版本。原版本不覆盖，仍可导出。编辑版导出 MP4、字幕和 Shotcut 工程时都读取本版本 EDL；父版本的字幕和渲染不自动转移。

## 指标定义

- **最终净切点修改秒数**：只比较基线与最终版本共有的片段，求每条源起帧和源止帧绝对移动量之和，再按该源视频的帧率换算。计算使用有理数，同时保存精确分数和显示数值。
- **调整片段数**：共有片段中任一源切点改变的数量。
- **新增／删除片段数**：根据稳定的素材与候选来源身份计算集合差，不按时间接近程度猜测匹配。
- **最少重排片段数**：只比较共有片段的相对顺序，以最长公共子序列计算移动数量的下界。删除或新增引起的序号变化不算重排。
- **新增片段的切点修改秒数**：单独与它自己的原始候选范围比较，不混入基线共有片段的修改秒数。
- **本次变化**：按相同定义比较直接父版本与本版本，单独保存，不能当作完整的操作事件日志。

例如：切点改动后恢复，最终净修改为零，但父子步骤仍能显示两次非零变化。删除第一条片段后，后面片段的成片时间会前移，源切点没有改变，因此切点修改仍为零。自动中心裁切到竖屏不算人工切点变化；已发生的净修改会保留。

切点秒数不等于编辑耗时，更不等于节省时间。网页当前没有可靠计时，发送 `editing_elapsed_ms=null` 并显示未记录；API 可接收用户明确记录的会话经过时间，不能从保存时间戳推断，也不能称作有效工作时间。

## 保存与验证

不改变两份冻结的 EDL Schema。人工编辑另存 `edit-record.json`，其哈希进入此版本的完成记录。每次读取时核对父版本、采纳基线、素材、候选快照及请求，再重建 EDL 和修改量；不能只信任文件里写出的高分或低修改量。共有片段的 provenance 完整保留，新增片段分配稳定且不碰撞的原选择编号。

父版本链有循环检测及 16 层上限，超过上限在发布前停止。网页的未知请求结果沿用既有恢复机制，不自动重试。历史版本没有修改记录时仍可使用，不能补填假零值或把版本数量当作修改量。

验证结果保存在工作区 `outputs/week4-edit-effort-validation/`，定向后端验证包括实际 MLT XML 切点／顺序检查和 MP4 服务传入 EDL 的检查；MP4 渲染器在该服务测试中是模拟的，不代表新版容器或真实帧级成片已验收。

最终验证：89 项后端定向回归、76 项前端测试全部通过；TypeScript、Vite 编译、修改文件 Ruff 与 Git 差异检查通过。统计示例与验证记录见 [evaluation/edit-effort-20261013](evaluation/edit-effort-20261013/README.md)。历史中止运行和测试桩修正前的失败记录均保留，没有冒充通过。

## 后续数据收集

此功能提供可测的修改量，不证明片段讲完事件，也不构成 85% 质量目标达标。后续需冻结话题生成策略，在未参与开发的素材上记录采纳与修改，并请第二位标注者盲评。真实编辑耗时与完整操作事件日志仍未收集，不能拿这批开发数据估计节省了多少劳动。
