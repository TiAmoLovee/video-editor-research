# 第四周整改：话题边界进入候选生成

2026-10-13。老师指出“句子没切断”和“事件讲完整”是不同粒度。本轮先实现可审计的前置话题分段，替换实验中的句子组合穷举；尚未发布或替换 8200 的生产候选流程。

## 生成方式

`decision/topic_segments.py` 在按时间排列的句子序列上工作。重叠句先组成不可拆单元，超过 3 秒的停顿先划定区间；每个相邻边界两侧最多取三个单元，以中文二／三字片段及英文词的 TF-IDF 向量计算余弦相似度。窗口不会跨过硬停顿。

在有测量值的曲线上寻找两侧都有上升的局部谷点，平谷采用确定的较早中点。谷深为 `(左峰 + 右峰 - 2×谷值)/(左峰 + 右峰)`，门槛固定为 0.15；保留原始深度供审阅。这能避免同形曲线因为整体相似度较低而被不同对待，但不能排除近零偶然词汇变化。相似度未知时记为 null，不能当作零相似度制造边界。

按谷深、相似度、原位置排序选择边界，保证相邻接受边界之间至少两个单元。每个候选只从完整话题段开头到结尾；15–90 秒范围外的段完整保留在拒绝报告中，不任意截短、跨话题补短，也不悄悄回退旧滑窗。单个重叠单元无法拆分。话题段只是词汇连续性基线，不是事件完整性的认证。

参数只冻结一组，没有对 New1–4 搜索权重或素材专用关键词。首次使用绝对谷深的诊断导致四份素材中三份无候选，已保留失败记录；在独立合成测试中确认尺度问题后改为相对谷深，阈值不变。后续材料仍属于已参与开发的数据，不能命名为盲测或泛化验证。

## 与现有工程衔接

- `generation.py` 捕获明确的策略及完整参数快照。未显式启用时仍使用 `sentence-window-v1`；新策略名为 `topic-valley-v1`。未知策略拒绝处理，不能自动降级。
- 新候选沿用评分和统一 EDL 契约，ID 绑定分析、生成版本、全部参数和原句。三份候选 Schema 同时支持新旧策略；旧 EDL Schema、历史产物和人工标签保持原样。
- 校验器按固定策略重算，拒绝半个话题、被删除的候选、伪造 ID 或隐藏拒绝原因。规则／模型评分只改变排序和评分，不改变原候选范围。
- 流水线另存并打包 `topic_segmentation.json`；缓存键包含策略及参数，恢复时重算验证分段，不能复用旧窗口冒充新生成。
- 话题策略关闭句子级边界修补，防止生成完整话题后再次截成句子碎片。旧修补只在显式旧策略下保留。
- 新算法使用标准库及已有依赖，不需要下载嵌入模型。句子数、文字数、分析字节和窗口宽度有明确上限；平谷证据按线性规模保存，越界直接停止。

本机实验可显式设置 `CLIPFORGE_CANDIDATE_GENERATOR=topic-valley-v1`。Docker 的 `compose.topics.yaml` 只提供配置，必须同时使用由这份源码构建的新 API 和 worker；不能把它直接套到旧镜像上冒充部署。本轮未更换现有容器，不要求重复上传素材。

## 工程验证范围

177 项定向回归通过，覆盖新旧候选生成、规则及模拟模型评分、缓存、选择、旧边界模块及统一 EDL。修改文件的 Ruff 检查和 Git 差异检查通过。离线对照与验证记录见 [evaluation/topic-generation-20261013](evaluation/topic-generation-20261013/README.md)。

这不是完整 CI 验收。全量运行遇到本机沙箱文件操作及本地 HTTP 访问限制后中止；定向运行明确排除了 11 项真实 HTTP／API 用例。原日志和中止记录保留在工作区 `outputs/week4-topic-validation/`。尚未验证新版容器、真实模型调用或新边界的成片质量，不能把 177 项通过解释为这些检查也已通过。

## 剩余验收

已有规则分 AUC／Top-5 离线诊断保留；同范围且有原始人评的模型分配对仍不足。话题生成后的质量要在策略冻结后使用未参与开发的素材验证。不能把候选数量减少解释为事件完整、吸引力或总体 85% 达标。

采纳后的人工修改量已经在本地接入第五周 EDL 编辑流程，见 [人工修改量](MANUAL_EDIT_EFFORT.md)：保留采纳基线、直接父版本和修改记录，区分最终净切点变化与本次变化，统计调整、新增、删除及最少重排数量。尚未部署，也没有真实编辑耗时或独立素材数据；后续需收集这些记录，并另安排第二位标注者盲评。

## 2026-10-21：新素材评审后的本地转写修复

冻结的 `topic-valley-v4 + rule-v1` 本地基线在 Kun1、Kun2、Apple1、Apple2 四段新素材中产生 10 条候选，由项目本人完成匿名顺序、隐藏分数的单人评审。9/10 条五项全通过（90%），但只有三段素材有输出；Apple2 为零候选。这是单人、小样本、所产生候选的观察结果，不代表系统在所有输入上稳定达到 85%。该基线原为诊断用途，在模型主实验校验失败后、人工反馈前增加人工评审；不能替代失败的模型主实验。

评审后开发回测改动如下，不回填原有标签：

- `local-word-coverage-recovery-v2` 保留原来的长缺口阈值、最多两处补查和每处一次解码。自动语言模式改在缺失区间自身检测语言；若与整片语言不同，去除异语言上下文再解码。用户明确指定语言时继续服从该设置。
- 若最后一个词所在的 Silero 语音区间，在词尾之后仍超过既有 VAD 填充长度，则有界检查短尾音，不再要求尾音达到三秒。该次解码不重复应用会滤掉短尾音的 VAD。只插入完全处于原空缺内的实测词条，不移动、延长或改写原词。
- 短尾音补查失败或仍未覆盖时，保留具体风险，由受保护的话题生成排除相邻片段；不得用一般长缺口审计为“清晰”冒充尾音已解决。无覆盖风险的普通素材不增加补查。

Apple1 补入一个词，原失败候选的结尾由 125.78 秒变为 126.34 秒；540p 研究预览多保留 17 帧，688 帧及音视频时长通过核对，解码音频与所请求原片区间的相关系数为 0.99975。这里没有新的人工通过标签。

Apple2 补入 90 个英文词条，但整段话题仍长于 90 秒，且尾部转写补查未完成，继续不输出候选。**候选覆盖问题尚未解决**，不能通过关闭保护或强制截到 90 秒来宣称修复。下一步需要改进话题边界与完整回答范围的对应关系。

本地 141 项相关测试通过，覆盖 ASR、句子、话题安全、缓存、EDL；沙箱内 HTTP 视频任务测试未完成，不能将其记为通过。此修复尚未发布部署，未调用百炼。原冻结批次仍为 9/10，旧批次 11/18 和失败的模型主实验均保留。结构化证据见 [local-asr-recovery-v2-20261021.json](evaluation/local-asr-recovery-v2-20261021.json)。
