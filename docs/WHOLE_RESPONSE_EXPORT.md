# 完整回答候选与保存工程

先识别话题、问答和因果关系，再生成候选。`topic-valley-v3` 和
`topic-valley-v4` 是可显式选择的本地策略；现有默认值及旧版本保持原样。
表面文字关系只是切点约束，不等于完整事件或吸引力已经得到人工确认。

对于已有的、绑定原始词序列的事件关系草案，新接口支持：

1. `POST /tasks/{task_id}/response-candidates`，请求体为 `{"proposal": ...}`。
   只预览完整回答候选并使用本地规则评分；不写文件，不调用模型。
2. 明确选择预览中的候选后，`POST /tasks/{task_id}/response-edl`，提交
   `proposal`、刚才的 `preview_sha256` 和按成片顺序排列的 `selected_ids`。
   任务或草案改变会拒绝保存。接口核验归一化媒体，再保存一个新的 EDL 版本。
3. 使用原有工程历史、字幕、MP4 和 MLT 接口导出；原任务、原候选和旧工程保留。

一个短回答种子不会直接充当回答终点；范围继续覆盖原始 ASR 所属段，直到
明确的新问题、话题切换或强制边界。不能在时长上限内完整表示的事件保留在
审计中，不把它切成短片以凑数量。无法确定语义结束的源文件尾部仍需审查。

此版本提供显式草案的预览和采纳接口；没有新增网页导入按钮，也不自动为新
上传视频请求事件规划。纯离线规划模块不会传输文字、读取密钥或重试请求。

周扬、Tim 四段素材属于已参与调试的回测集。旧人工结果保留为 11/18；新生成
范围不能继承旧片段的人工标签。结构检查、媒体导出成功与人工质量通过率分别
报告。没有新的人工标签时，不声称达到 85%。
