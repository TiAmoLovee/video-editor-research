# 第五周：统一剪辑清单与可继续编辑的工程

2026-10-12 根据原任务书第 9–10 页及老师反馈调整工作主线。原任务书第五周明确建议优先打通 EDL → MLT → Shotcut；此前候选工作不应继续占用这一交付。

## 原第五周交付

1. `edl.json` JSON Schema，以及用户指定候选到 EDL 的转换。
2. EDL → MLT XML 工程导出。
3. EDL → FFmpeg 精确帧级渲染。
4. 9:16 输出，基础版先选固定中心裁剪。
5. SRT/ASS 字幕生成与烧录。

任务书要求三个导出器核心覆盖率 ≥80%、至少五个 MLT 样例及渲染样片。Shotcut 打开后，片段数量、顺序、源素材起止时间与 EDL 一致，切点误差 ≤1 帧；字幕与语音的人工抽检目标 ≤0.3 秒。生成 XML、单元测试通过或底层 MLT 能加载，均不能代替 Shotcut 的实际打开验证。

第一步已实现 EDL 0.1.0 原型、明确候选选择/排序转换和 MLT 导出，新增 18 项单元测试通过；当时的五个工程经实际 MLT 7.41.0 引擎渲染，独立解码核对 226 帧全部一致。运行方式与限制见 [EDL/MLT 原型](EDL_MLT.md)。这些历史结果不替代后续效果的核验。本地代码尚未推送或部署，第五周整体验收仍未完成。

## 为什么不继续补句子边界

目前 `decision/candidates.py` 是句子滑窗，每句起点枚举后续句终点。`decision/topics.py` 是候选生成和时间去重之后的词汇分组，不能阻止最初产生不完整事件片段。

原任务书第四周的 85% 定义是“首尾未截断半句”，不是“完整表达一件事”，更不是“吸引人”。New4 的 17/19 是单批次的既有人工结果，不扩展为不同素材的普遍成功率。此前修复实验有已知反馈参与；这些记录继续保留，不重新命名为独立泛化结果。

相邻文本窗口相似度及谷点可作为话题段生成的基线，但话题段不等于完整事件。短话题、超过时长上限的长话题、问答依赖、开头缺前提以及 ASR 错误必须明确处理；不通过任意截短、排除失败样本或新增针对某素材的尾词规则来保证表面达标。一次冻结生成方法后，再检查未参与开发的素材。

## 现有评分的离线诊断

脚本与原始匹配表位于工作区 `outputs/week5-scoring-audit/`，按素材、候选身份、原边界、原文和哈希匹配，没有新模型调用、改标签或混入修复后的版本。

| 原始批次 | 明确正/负标签 | 规则分 AUC | Top5 四项全通过 |
|---|---:|---:|---:|
| New1 原始 10 条，排除 2 条不确定 | 5 / 3 | 0.20 | 2/5 |
| New2 原始 8 条，单独补充报告 | 7 / 1 | 0.5714 | 4/5 |

AUC 的同分比较计 0.5；Top5 按分数降序，并报告截点同分的期望与上下界。New1 将不确定保留为未接受的敏感性分析为 AUC 0.36、Top5 2/5，不修改原标签。

历史“21 条”指 New1 3 条、New2 8 条、New3 10 条已确认版本，包含重叠及人工另选成片；不能据此构造一个 21 条原始正负标签集。只有已接受数据时 AUC 不可计算，而不是 0.5。此次可配对记录中没有同范围的真实 LLM 评分，不能编造规则与模型的公平对比。以上小型开发数据只支持暂停围绕旧规则微调，不支持给出总体统计结论。

## 首版数据与互操作范围

- EDL 是后续渲染和导出的共同事实来源。用户明确选择候选及顺序；评分不自动变成采纳决定。
- EDL 使用整数帧和有理数帧率，片段结束位置不包含在内；MLT `out` 是包含的最后帧，转换为 `end_frame - 1`。
- EDL 首版覆盖素材引用、单视频轨、原音轨、片段范围和顺序；字幕由带哈希绑定的派生计划生成。MLT 已接入保存的固定中心裁切及字幕计划，新版字幕为精确整数帧纯文字 qtext／深色背景，ASS 则向内量化为厘秒并使用描边；不承诺逐像素相同。重复含音来源用独立片段解码器，首帧单帧字幕另有 opacity 门控。含音单帧片段存在确认的 MLT 音频缺失，明确拒绝并提示导出 MP4；无声单帧支持。五例 GUI 打开另存回读已通过，crop 实际修改及 RichText 文字提交保存另有独立记录；新版字幕编辑样式保持已在当前 96 DPI 核验，旧失败记录保留，跨机器字体仍待验收，复杂转场及多轨未完成。
- 已确认的 CFR、视频尺寸、旋转和音轨索引由明确的媒体描述提供。不能仅凭平均帧率把任意原片认定为 CFR。
- 文件导出不打包原始素材；跨机器需一并携带素材或重新定位引用。
- 本地已增加已有任务的 EDL 保存/读取及下载服务，React 工作台已接入本地预览并通过一次真实导出流程；生产尚未部署。原任务结果、历史人评和远端仓库保持原状。

## 后续可测指标

将用户采纳时的初始范围作为基线，保存最终范围及操作记录：

- 边界修改量：每个片段 `(|最终起点−初始起点| + |最终终点−初始终点|) / fps`，按秒累计；起止修改不互相抵消。
- 调整片段数：边界或顺序被修改的唯一片段数量；另记新增、删除片段数。
- 接受比例、实际编辑耗时及素材类别分别报告。修改少不必然表示吸引人，也不能通过删除失败片段把指标变好。

第六周在人工复核界面记录修改，第七周再检查标注者一致性。停止要求用户对同一批旧片段重复评判。
