## 已实测的性能

处理前按原冻结顺序选择第一份来源 V030，186.116667 秒、91,014,067 字节。固定顺序为 CPU 冷／热，再 CUDA 冷／热，每种一次；未按人评结果或测速挑片，也未重复试验选最好的一次。

计时从第一字节 HTTP 上传前开始，到完整 ZIP 下载并写入本地为止，包含排队、worker 全部处理、缓存发布及轮询。启动服务、预装依赖和本地模型文件准备、输入哈希预检、下载后审计另计。冷路径采用新 worker 与空应用结果缓存；没有清除操作系统磁盘缓存，模型对象首次加载包含在任务内。

CPU 请求 int8，实际 CTranslate2 后端为 CPU/int8_float32；CUDA 请求和实际后端均为 CUDA/float16。两条冷路径都验证了非静音语音、固定权重身份、真实模型加载及转写调用；热路径均零模型加载、零转写，缓存中的 ASR 耗时是原任务值，不冒充本次计算。

设备为 Ryzen 9 5900HX、16 逻辑处理器、16,558,161,920 字节物理内存、RTX 3070 Laptop 8 GiB、驱动 617.42，Python 3.11.9／Windows build 26300。ASR 固定 base 权重、4 CPU 线程及一个模型 worker。NVIDIA 的 8 GiB 是容量，未测显存峰值；表中为客户端、API、worker 及子进程的采样工作集之和，可能包含共享页，不能视为唯一物理 RAM。提交量与实际采样间隔另见 JSON；250 ms 是名义间隔，两条冷路径实际平均约 278–280 ms。

运行架构为真实 Uvicorn HTTP API、独立 Celery solo worker、filesystem broker 和 SQLite 状态库。测试使用独立数据目录、单 worker、顺序任务，主机其他应用未关闭；它不是 Redis／Docker 或独占空闲机器的基准。原生产 8200 服务和已有任务没有部署变更；测试进程已退出，两个测试端口已通过独占重绑确认释放。

ASR 组件分别用时 **24.392／9.961 秒**；镜头组件用时 **312.462／327.506 秒**。本例主要耗时仍在 CPU 镜头检测等阶段，整体没有观察到 CUDA 路径加速。两种精度产生 505／513 个词、107／115 个候选，恢复调用次数也不同；固定顺序、单样本和工作量差异不支持把耗时差解释为纯硬件因果效果，字数增加也不是准确率提高的证据。

四份下载 ZIP 的 SHA、每份 18 项 CRC／实际服务文件、Schema、四份上传原片、固定权重及运行依赖均核验。两条路径的归一化视频和七个输出视频逐字节一致；每份计划为 6×900＋184＝5584 帧。应用、基准脚本、依赖在运行前后保持相同字节，基准没有重试。此流程测量自动分析、候选生成与基础切片 ZIP；人工编辑、另存 MLT 和浏览器交互响应未并入该计时。

## 工具与交付边界
