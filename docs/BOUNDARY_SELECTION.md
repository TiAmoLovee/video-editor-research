# 边界修正草案与时间去重

Test3 的最高分候选为 1.43–19.74 秒，但用户确认结束时已经混入拿书签名的新场景。逐帧检查发现视觉切换在第 535 帧（30 fps，17.8333 秒）；旧镜头分析漏检，ASR 又把“面”标在 17.72–17.90 秒。直接按视觉切点裁剪会与转写字词边界冲突。

## 本步行为

新增 `clipforge.decision.selection`，从已保存的 analysis 与 candidates 生成独立的 `boundary-nms-v1` 结果。原分析、评分、候选 ID、ZIP 和实际切片不改写，不请求模型。

- 使用检测到的镜头边界，以及显式导入的人工场景记录。人工记录同时绑定原片和归一化视频 SHA256，时间使用整数帧与固定 30 fps；不根据文件名、用户账号或 Test3 时间硬编码算法。
- 候选边缘 3 秒以内出现镜头切换时给出复核提示。人工确认的话题切换即使在候选中间也标记。普通镜头切换不自动等同于话题切换。
- 修正草案只缩短原范围。切点跨字词时，最多向后寻找 0.15 秒内的完整词结束点；仍有交叉词或新范围不满足 15–90 秒时，不生成草案。保留原词 ID、原句 ID、原词文字及移动距离。
- 草案始终标记 `review_then_rescore`、`score=null`、语义完整性未验证。词对齐也可能有误；不把字词完整视为声音或语义验收通过。长范围中间跨话题本轮只标记，未自动拆分成多个新候选。
- 时间 NMS 按原候选的已有分数/稳定排名遍历，与已保留项的时间 IoU ≥0.5 时折叠；记录被谁折叠与实际 IoU。NMS 使用原范围，不借用旧分数给修正草案排序。它不保证零重叠，不实现主题去重或聚类。
- 模型的 incomplete、needs_context、uncertain 完整性判断也显示“边界待复核”；没有问题信号的候选仍显示“完整性未人工验收”。去重保留不表示质量合格。

这些参数为首版工程默认值，未经跨素材调优。修正后的真实候选重建、重新评分及渲染尚未实现，本步不能当作最终边界修复验收。

## 页面与已有任务

候选接口支持 `view=all|retained`，按全批去重结果分页，保留原排名。现有成功任务可直接使用，不必重新上传或调用百炼。`GET /tasks/{id}/selection` 下载当前算法版本的复核记录；记录包含输入哈希、人工证据和参数，是新生成的独立报告，不冒充原始 ZIP 产物。

人工记录保存在对应任务目录 `boundary_review.json`，不进入原任务完整流程缓存，也不自动传播到别的任务。不存在人工记录时只使用该任务的镜头检测结果。错误的媒体身份或损坏记录使该复核接口明确失败，不静默丢弃问题；原始切片下载仍可用。

CLI `python -m clipforge.decision.selection --task-id UUID --review PATH` 仅用于安装已明确确认的人工记录：成功任务、正确媒体身份、输入评分校验通过后才写入。重复导入同一记录幂等；已有不同记录时拒绝覆盖。不会读取模型密钥或调用评分器。HTTP 只读查询不写入记录。
