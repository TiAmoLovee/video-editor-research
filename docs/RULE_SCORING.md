# 第四周第二步：可解释规则评分

本步在第一步离线候选生成之后运行，保留每个候选的起止时间、原始文字、ID 和来源句子，新增评分及排序。未接入任务服务和前端，未调用 LLM，也不代表第四周整体验收。

## 接口和产物

- `Scorer` 定义 `score(candidate, analysis, audio)` 抽象接口。
- `ScorerRegistry` 提供工厂注册及实例化，拒绝重复名称、未知评分器和不合规返回值；默认注册 `rule`。
- `RuleScorer` 是第一种实现，LLMScorer 尚待后续开发。没有用占位实现冒充第二种评分器或断网降级。
- `config/scoring/rule-v1.json` 保存版本化参数与关键词，无需改代码即可调整。
- 输出采用独立的 `scored_candidates.schema.json`，版本 `0.1.0-draft.2`。旧的 pending 窗口草案仍可使用，analysis 0.1.0 保持不变。
- 每个候选含 `score`、`scorer: rule`、`reasons[]`、`features`、`rank` 和 `source_sentences[]`。每个分项保存归一化值、加扣分和原始测量依据。
- 保存完整窗口哈希、配置及其哈希、音量来源哈希。验证时还原窗口并检查哈希，防止评分期间改动边界、文字或候选集合。

## 默认计算规则

总分为 `clamp(20 + 35K + 15P + 15V + 15Q - 20D, 0, 100)`。分项值均在 0–1 范围内；贡献保留 6 位小数，总分由贡献相加后截断得到。按总分降序、起点/终点/ID 升序打破同分，排名可复现。

| 项 | 测量与归一化 | 默认最多贡献 |
| --- | --- | --- |
| K 关键词密度 | 从左到右最长关键词优先，重叠不重复计数；命中字符数 / 全文有效字符数，再除以 8% 并截断到 1 | +35 |
| P 语速变化 | 每句有效字符数 / 句子跨度秒数；相邻句速率绝对差均值 / 各句速率均值，再除以 0.5 并截断到 1 | +15 |
| V 音量峰值 | 候选最大 100ms RMS dBFS 与全片有效音量帧中位数之差；除以 12 dB 并截断到 1 | +15 |
| Q 问答提示词 | 问句提示词之后，同句或之后两句内出现回答提示词即记 1；保留句子配对证据 | +15 |
| D 时长惩罚 | 与 30 秒目标时长的绝对差 / 30，截断到 1 | -20 |

有效字符是 Unicode 字母或数字（中文计字，不冒称分词结果）。语速包含句子内部停顿，不是剔除全部静音后的发音速度。默认关键词为“关键、原因、方法、总结、注意、为什么、怎么”；不为 Test3 单独调词或权重。

音量有效帧阈值为 -60 dBFS；全静音、无有效帧或无峰值不奖励。还记录 sample peak dBFS，但排序使用 100ms RMS 峰值，以降低单采样尖峰影响。无原音频证据时该项为 0，其他项不重新分配权重，并明确记录 unavailable。分数是启发式优先级，不是概率或已测准确率，不应跨配置或缺失信息条件直接比较。

## 音量来源与对齐

`measure_audio` 只接受与 analysis.normalized_sha256 完全匹配的归一化视频，并检查时长、H.264/30fps 和音轨状态。复用第三周的 PCM 提取逻辑，保留音视频相对偏移并补齐首尾，不把晚开始的音轨移到视频零点。提取后再次验证视频哈希。

16kHz 单声道 16-bit PCM 按 100ms 分帧，尾帧不补入计算之外的样本。候选选取帧中心落在区间内的帧，量化误差小于 100ms。基准是全片高于 -60 dBFS 帧的 RMS dBFS 中位数。保留 PCM 样本字节 SHA256，以追踪解码结果。

明确提供了错误视频、损坏音频或不可用工具时失败，不静默使用另一个视频。未提供视频时可以完成文本部分评分，但会标记缺失证据。此行为不是 LLM 故障降级功能。

## 复跑

仓库根目录、已安装后端和 worker 依赖的 Python：

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
python -m clipforge.decision.scoring analysis.json windows.json --normalized-video normalized.mp4 --output scored.json
```

如工具未在 PATH，使用 `--ffmpeg`、`--ffprobe` 或项目已有的环境变量。可用 `--config` 指定配置 JSON。输入或已有输出不会被覆盖。没有对应视频可省略 `--normalized-video`，但结果将明确缺失音量。

```powershell
python -m unittest discover -s backend/tests -p test_scoring.py -v
python -m unittest backend.tests.integration_rule_scoring -v
```

第二条需要 FFmpeg/ffprobe，会创建真实延迟音轨视频，验证首尾静音、PCM 对齐和评分全流程，不调用 ASR。

## 当前限制与下一步

关键词、语速波动、音量和问答提示词都是启发式信号；音乐/噪声也可能触发音量加分，语速波动不一定意味着精彩内容，ASR 错字会影响文本信号。尚无人工质量评分或参数调优结论，不能宣称语义完整率 ≥85%。

下一步把生成与规则评分接入后台任务、下载和页面，并处理缓存键/结果兼容；部署验证后再接入 LLM、故障降级、边界吸附、NMS、主题去重及对比评测。
