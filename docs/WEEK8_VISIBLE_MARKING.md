# 第八周：全出口显式水印

2026-11-04。本轮补齐所有新成片路径的“AI辅助剪辑”，范围是工具生成的交付视频与预览，不包括原始上传素材、分析中间视频和历史冻结输出。旧成片、人工评分、原字幕计划和原媒体哈希保持原样。

## 实现与运行前提

| 路径 | 标识实现 | 发布前验证 |
| --- | --- | --- |
| 普通 EDL MP4、ZIP 内每一片 | 独立全时段 ASS，右上角白字黑边 | 字体文件身份、中文字符覆盖、实际字体选择、帧数、原时轴、元数据 |
| 带字幕 EDL MP4 | 继续使用原 ASS 中唯一品牌行 | 原字幕验证与上述检查共同执行，不重复叠加标签 |
| 自动 30 秒切片 | 每片通过共享水印会话烧录 | 完整批次逐片核验后发布，尾片亦覆盖 |
| 优化预览、评测片段、词边界复核 | 在最终 540p 缩放后烧录 | 精确源范围、30 fps、音频时长、元数据与渲染证明 |
| MLT 工程 | 无论是否带字幕，都带唯一全时段 qtext 品牌滤镜 | 工程结构和版本读回；原生 melt 合成视频逐帧检查 |

FFmpeg 新成片需要支持 `ass`／libass 的构建，以及同时设置 `SUBTITLE_FONT_FILE` 和 `SUBTITLE_FONT_NAME`。字体名称必须对应文件内家族并覆盖“AI辅助剪辑”；缺字体、缺字、滤镜缺失、字体替换或渲染期间输入变化都会报错。不会自动改用未核验字体或继续输出无标识成片。

画布还必须容纳完整标识文字框；极窄或极矮尺寸会在编码前拒绝。审阅曾复现 160×2 画布标识落到画外的反例，修复后新无字幕和字幕导出均预检，原反例与修复证明分别保留。

```powershell
$env:FFMPEG = "C:/tools/ffmpeg/bin/ffmpeg.exe"
$env:FFPROBE = "C:/tools/ffmpeg/bin/ffprobe.exe"
$env:SUBTITLE_FONT_FILE = "C:/Windows/Fonts/msyh.ttc"
$env:SUBTITLE_FONT_NAME = "Microsoft YaHei"
$env:PYTHONPATH = "$PWD;$PWD/backend"
```

以上 Windows 字体示例仅使用本机已有文件，不随仓库分发。也可使用覆盖所需字形的 Noto 字体。API 与 worker Dockerfile 均安装 `fonts-noto-cjk` 并配置 `Noto Sans CJK SC`；默认Dockerfile的验证与现有服务的兼容部署分别记录，见后续本机验收。原生程序不自动载入 `.env`。

新 MLT 的完成记录升级为 format 3，冻结 `brand_policy_version=1` 与字体名称；旧 format 1／2 按原策略生成、核验，避免新政策破坏历史文件读取。Shotcut 所在机器需安装相应字体。工程可编辑，外部工具删除滤镜、替换字体或另选编码参数后需要重新检查；本轮不保证外部成品带项目自定义元数据。

缓存身份包含实际字体 SHA-256 与标识策略；当前缓存读回必须有匹配的逐片水印证据，旧未标记缓存不能被当作新成片复用。新增人工验收导入要求渲染证明与已验收媒体 SHA、全时段、字体、ASS、元数据相绑定；单独自报字段不够。已有历史记录可原样读回与幂等提交，缺失旧媒体不得借重导入静默修复。此证明是可信本地渲染器的一致性检查，不是任意外来 JSON 的真实性认证。

## 实际画面验收

真实媒体均为新建合成数据，包含明暗背景、横屏、9:16 中心裁切、完整画面留边、有／无音轨、带／不带字幕。没有重编码第七周视频或重填人评。

| 检查 | 本轮结果 | 证明范围 |
| --- | --- | --- |
| EDL 18 个视频 | 3,240 帧逐帧水印检查通过 | 水印区域独立于中央源帧条码；条码读回确认源帧顺序与切点，音轨存在性保持 |
| ZIP 3 个片段 | 共 28 帧通过 | 每片水印、首末源帧与切点误差 0 帧；原清单保留 |
| MLT 5 个场景 | 共 69 帧通过 | 原生 melt 渲染；水印外与透明文字对照的 RGB 完全一致，含无声单帧 |
| 自动切片、优化／评测预览 | 独立真实媒体用例通过 | 跨 900 帧分界与末尾单帧、首中末标签、540p 输出及音频尾部 |

截图已检查标签完整性、明暗背景可读性、右上角留边、底部字幕分离和无重复标签。逐帧像素检查检测预留区域的对比文字，不能识别任意输入视频中文字的语义；因此同时保留固定文本／字体验证和截图核查。`tools/week8/check_export.py` 仍只检验元数据，其成功不代表显式水印已检查。

完整回归结果与版本身份保存在本轮测试记录中。本次使用真实带 libass 的 FFmpeg；另一个本机 FFmpeg 构建不带 libass，已验证其被明确拒绝。最初挂起的 HTTP 测试定位为执行环境拒绝本机回环连接，获准网络访问后正常执行。Windows 执行沙箱还拒绝硬链接，依赖该操作的原子验收导入测试需由正常 CI 环境验证，不能通过修改产品或替换测试结果冒充完成。

最后一轮相关渲染／字幕／MLT／批导回归 97 项通过、0 跳过；换行规范化后 21 项核心复测通过。首次全量 1,168 项的具体失败、修复和环境限制记录在 [本轮证据](evaluation/week8-visible-marking-20261104/README.md)，不将该首次全量记为全通过。
