## 第一步实现

新增 `clipforge.decision.candidates`、草案 Schema 和来源校验。先验证冻结的 analysis 0.1.0，再以每个句子单元为起点、每个后续句子单元为终点枚举合规窗口，步长为一个单元。沿用 normalized_video 时间轴。

- 重叠句子组成不可拆分单元，避免截断相邻句子；保留原句 ID、原文、时间、确定性候选 ID 和来源哈希，不改原分析。
- 默认最大句间停顿 3 秒，是项目暂定参数，不是任务书要求或经验证的最优值；可用 `--max-gap-seconds` 修改。
- 不足 15 秒不补静音；超过 90 秒的单句/重叠组跳过并警告；空转写、无音轨返回带原因的空列表。
- 默认最多 10000 个候选，超限明确失败，不静默截断；后续按实际规模调整上限和采样策略。
- 输出版本 `0.1.0-draft.1`，`artifact_kind=candidate_windows`、`stage=generated`。所有候选均为 `scoring_status=pending`、`score=null`、`scorer=null`、`reasons=[]`，没有假评分。
- 完整 JSON 规范化后的分析哈希用于追溯，与第三周忽略计时字段的内容哈希不同，不可互换。
- 独立 CLI，未改 API、worker、缓存、前端和下载列表；无需重建服务，网页仍保持第三周行为。

从仓库根目录使用已安装后端依赖的 Python：

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
python -m clipforge.decision.candidates PATH_TO_ANALYSIS.json --output PATH_TO_NEW_CANDIDATES.json
python -m unittest discover -s backend/tests -p test_candidates.py -v
```

输出路径必须不存在，不能覆盖输入。后续评分模块写出新的 scored 草案；当前草案未冻结。
