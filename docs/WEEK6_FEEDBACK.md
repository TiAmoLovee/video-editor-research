## 真实长片暴露的批导问题与修复

源录像为 1920×1080、30 fps、6856 帧／228.533 秒。三个保存范围重排为 [3600,3900)、[600,900)、[2700,3000)，各 300 帧。首次在重复完整解码同一源时接近原 90 秒预算而失败，没有发布 ZIP；失败记录保留。

修复后只在一次活跃批导的持锁上下文内复用首次实际来源测量；每次复用仍核对文件身份和完整 SHA，每份输出仍全帧检查 CFR／PTS／尺寸、帧数、音轨及哈希。普通渲染的默认校验保持。去除批导内仅为重复计数而进行的第二遍完整解码，不调大 90 秒时限。

同一实验重跑耗时 **75.906 秒／90 秒**。全部 900 帧最小全分辨率 SSIM 为 **0.988409**；783 帧能清楚匹配预期邻域源帧，117 帧与相邻静止／重复画面存在歧义，未宣称每帧都可唯一定位为“0 帧误差”。来源准备保存 EDL 使用单独 360 秒测量预算，本轮不是浏览器 HTTP 或采纳接口 90 秒的端到端验收，也不是多素材吞吐基准。

新增 8 项安全／性能回归；50 项相关检查为 49 通过、1 项按 Windows 策略跳过。覆盖首次实际测量、不可灌入历史快照、写入／替换防护、不同批次重新测量、关闭上下文拒绝复用与每份输出完整校验。新提交远程 CI 以其 Actions 记录为准；旧四项全绿不替代本轮检查。
