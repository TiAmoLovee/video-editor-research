# 第六周工作台本地使用与验收

第六周已整合到 `main`，并完成作者本机部署与验证。老师可以从 GitHub 下载代码 ZIP，在自己的电脑运行；下面从首次上传开始，不依赖作者的历史任务。

## 启动工作台

将代码 ZIP 完整解压，按 [README 的 Docker 启动步骤](../README.md) 安装并启动 Docker Desktop，在包含 `compose.yaml` 的项目根目录执行文档中的命令：构建服务，在 Docker 内下载并校验固定版本的 base 转写模型，再启动工作台。模型不捆绑在代码 ZIP 中，首次准备需要联网。Docker 内已包含运行所需的 Python、Node.js 和 FFmpeg；默认使用 CPU，无需显卡。

启动完成后，在这台电脑的浏览器打开 <http://127.0.0.1:8200/>。这个地址访问的是当前电脑上的程序，GitHub 页面本身不运行工作台。

默认使用本地转写与规则评分，自动首尾优化关闭，**不需要 API Key**。初次使用无需启用 LLM 或边界优化的附加配置。

## 从上传到导出

1. **上传并等待分析完成。** 选择自己有权使用的一段清晰讲话视频，点击“上传并开始处理”。首次体验建议使用约 30–90 秒、讲话连续、背景音乐较少的素材。完成后在任务详情查看原视频、转写和候选。过短、静音或没有可识别讲话的素材可能没有候选，不能用于完整体验下面的复核与编辑流程。

2. **点击文字试听并记录复核决定。** 点击转写句子，视频会定位到对应时间，再播放核对。填写“复核操作人姓名”，查看候选的评分与理由，选择“采纳”或“驳回”；理由可选，也可撤销为待复核。刷新页面后可检查决定是否保留。姓名是操作者填写的记录，不代表登录身份。

3. **明确选择成片片段并保存。** 勾选要加入成片的候选，调整“待保存的片段”顺序，确认“操作记录姓名”，点击“保存选择为剪辑版本”。采纳决定与加入成片分别记录；只有保存剪辑版本后，选择和顺序才成为可导出的 EDL 剪辑清单。

4. **调整时码并另存版本。** 在已保存版本中点击“编辑这个版本”，在原范围附近小幅调整入点、出点，也可增删或重排。输入秒数或“时:分:秒”时码会对齐最近的视频帧，也可用整数源帧精调。起点包含、出点不包含，且入点须早于出点。点击“保存修改为新版本”，刷新后核对范围与顺序。

5. **导出 MP4 与逐片 ZIP。** 确认“导出版本”选中刚保存的版本，点击“导出 MP4”，完成后预览或下载。在逐片导出区域点击“生成批量片段 ZIP”，再下载该版本的片段 ZIP。ZIP 包含每段 MP4、EDL 与片段清单；导出使用已保存版本，不会采用尚未保存的草稿。需要竖屏时，可另存“完整画面 9:16”或“居中裁切 9:16”版本，再选定对应版本导出。

6. **检查操作审计。** 展开“人工操作记录 · 复核与剪辑修改”，核对姓名、时间、候选和修改前后值，也可点击“下载完整操作记录”保存 JSON。遇到“操作结果尚未确认”时，先等待并刷新对应记录，核对结果后再继续。

普通关闭和再次启动的方法见 [README](../README.md)。保留 Docker 数据卷，才能继续读取自己创建的任务、复核决定和剪辑版本。

## 验证范围与质量限制

本次整合的前端 121 项测试、类型检查和构建通过，后端 193 项相关回归通过，覆盖文字定位、复核与恢复、时码编辑、审计及批量导出，并保留原有画面适配、整段回答和字幕修时能力。既有工程闭环与逐帧证据见 [第六周交付记录](WEEK6_DELIVERY.md)，各记录保留其原始验证范围。

使用时仍需试听并核对转写、候选边界、内容完整性和画面取景。合成素材的帧精度验证不代表真实叙事质量、所有素材的转写准确率或真人语音同步已经达标；规则评分也不等同于人工验收。

2026-10-26 的真实素材、字幕数字与评分配对范围见[教师反馈修改记录](WEEK6_FEEDBACK.md)。
