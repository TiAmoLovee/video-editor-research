# 第六周交互工作台与验收

第六周增加文字与视频联动、候选复核、时码编辑、操作审计和逐片批量导出。人工修改保存为独立 EDL 版本，再按该版本重新渲染；原任务结果及素材保留。当前为待验收交付，浏览器完整闭环仍需在可访问本地服务的环境补验。

## 使用流程

1. 选择已完成且有转写和候选的任务，点击转写句子，将原视频定位到对应时间，再播放试听。
2. 填写操作人姓名，在候选卡片查看评分及理由，选择采纳、驳回或撤销复核。复核状态会保存；进入成片的候选由勾选和保存顺序决定。
3. 勾选所需候选并保存 EDL。点击人工编辑，输入秒数或 `HH:MM:SS.ffffff` 时码，也可直接修改整数源帧；可重排、增删片段。
4. 保存新版本后生成 MP4。批量导出按当前保存版本的顺序，生成每段 MP4 及一个 ZIP，附 EDL、片段清单和校验值。
5. 查看操作审计，核对操作人、时间、片段及修改前后值，或下载 JSON。

时码按保存版本的有理数帧率换算到最近帧；出点采用不包含该帧的区间。未保存的草稿不参与导出。姓名为用户填写的记录，旧版本未记录的姓名显示为未记录。

## 保存与恢复

复核事件保存在独立 SQLite 文件，事务内按任务和请求编号去重，拒绝修改或删除已保存事件。复核同时绑定候选快照，旧快照请求不会改写当前候选。采纳基线和手动修改各自保存姓名及时间，手动修改另保存完整前后值和边界、排序、增删操作。

响应丢失后页面保留原操作编号，先查询结果；只有明确确认未保存时，才由用户重新提交同一次操作。浏览器拒绝会话存储时，当前页面进程内仍保留待确认请求。确认旧请求后重新读取当前状态，避免覆盖其他窗口较晚的决定。批量导出也按原编号恢复，普通 HTTP 环境支持随机编号生成回退。

原视频读取、导出和下载继续校验归一化素材及保存证据；失败的渲染不会发布完整版本。冻结 EDL schema 保持原样，旧 API 调用和旧版本可继续读取。

## 验收证据

前端 117 项交互测试通过，类型检查和生产构建通过。测试覆盖文字跳转、任务切换、迟到响应、复核保存和未知结果恢复、时码及姓名校验、保存版本绑定和批量下载。后端测试覆盖复核事务、审计前后值、幂等、版本隔离、路径和素材校验，以及既有编辑和导出回归。720 项本地测试中，修正临时目录及测试工具环境后累计 712 项通过、1 项跳过，7 项既有导入测试受 Windows 硬链接权限阻挡；Ruff 和差异格式检查通过。独立 CI 结果以 PR 为准。

真实注册路由闭环完成 22 次调用，包含采纳和驳回、请求编号恢复、保存基线、修改与重排、MP4、批量 ZIP、审计下载及视频范围读取。修改后的两个片段为 `[303,595)`、`[2,297)`，总计 587 帧。独立逐帧解析确认全部源帧和顺序一致，切点误差 0 帧，原任务及源素材保持原样。此验证直接调用实际注册路由函数，未验证 HTTP 传输及浏览器操作；[闭环记录](evaluation/week6-engineering/routes-roundtrip.json)和[逐帧解析](evaluation/week6-engineering/decoded-roundtrip.json)保留验证方式。

批量专项使用带完整源帧编号的合成视频及 48 kHz 音频，修改后导出三段，共 28 帧。逐帧解码确认源区间和片段顺序，切点误差 0 帧，音频样本预算一致；[批量验证记录](evaluation/week6-engineering/batch-real-media.json)保留全部帧编号。合成结果验证精确切片，不用于判断叙事质量或真实人声同步。

本次环境的浏览器无法连接新启动的本地 HTTP 服务，因此“真实网页修改、保存、重新导出、逐帧解析”的整体验收尚未完成。接口闭环与前端交互测试分别保留验证方式，不将其记为浏览器验收通过。部署前应在可访问服务的环境完成下列步骤。

## 浏览器待验收步骤

1. 打开一个已有任务，点击中间转写句，核对播放器实际时间；刷新后检查采纳和驳回仍保存。
2. 保存两个候选，输入非整数秒的入出时码，并重排一次；保存后刷新，核对 EDL 的帧范围、顺序及姓名。
3. 对该保存版本重新生成 MP4 和批量 ZIP；解析全部输出帧，与指定源区间比较，切点误差必须不超过 1 帧。
4. 检查审计姓名、时间、完整前后值；确认旧 EDL、原素材和原任务下载仍可读取。

独立素材的叙事质量及 85% 指标继续按既有评测记录处理；本周工程测试不替代独立人工评测。
