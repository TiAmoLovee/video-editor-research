## 使用流程

1. 选择已完成且有转写和候选的任务，点击转写句子，将原视频定位到对应时间，再播放试听。
2. 填写操作人姓名，在候选卡片查看评分及理由，选择采纳、驳回或撤销复核。复核状态会保存；进入成片的候选由勾选和保存顺序决定。
3. 勾选所需候选并保存 EDL。点击人工编辑，输入秒数或 `HH:MM:SS.ffffff` 时码，也可直接修改整数源帧；可重排、增删片段。
4. 保存新版本后生成 MP4。批量导出按当前保存版本的顺序，生成每段 MP4 及一个 ZIP，附 EDL、片段清单和校验值。
5. 查看操作审计，核对操作人、时间、片段及修改前后值，或下载 JSON。

时码按保存版本的有理数帧率换算到最近帧；出点采用不包含该帧的区间。未保存的草稿不参与导出。姓名为用户填写的记录，旧版本未记录的姓名显示为未记录。

## 保存与恢复

复核事件保存在独立 SQLite 文件，事务内按任务和请求编号去重，拒绝修改或删除已保存事件。复核同时绑定候选快照，旧快照请求不会改写当前候选。采纳基线和手动修改各自保存姓名及时间，手动修改另保存完整前后值和边界、排序、增删操作。

响应丢失后页面保留原操作编号，先查询结果；只有明确确认未保存时，才由用户重新提交同一次操作。浏览器拒绝会话存储时，当前页面进程内仍保留待确认请求。确认旧请求后重新读取当前状态，避免覆盖其他窗口较晚的决定。批量导出也按原编号恢复，普通 HTTP 环境支持随机编号生成回退。

原视频读取、导出和下载继续校验归一化素材及保存证据；失败的渲染不会发布完整版本。冻结 EDL schema 保持原样，旧 API 调用和旧版本可继续读取。

## 浏览器复验步骤

1. 打开一个已有任务，点击中间转写句，核对播放器实际时间；刷新后检查采纳和驳回仍保存。
2. 保存两个候选，输入非整数秒的入出时码，并重排一次；保存后刷新，核对 EDL 的帧范围、顺序及姓名。
3. 对该保存版本重新生成 MP4 和批量 ZIP；解析全部输出帧，与指定源区间比较，切点误差必须不超过 1 帧。
4. 检查审计姓名、时间、完整前后值；确认旧 EDL、原素材和原任务下载仍可读取。

独立素材的叙事质量及 85% 指标继续按既有评测记录处理；本周工程测试不替代独立人工评测。
